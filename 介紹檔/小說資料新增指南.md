# 小說資料新增指南

本指南說明如何新增小說世界、篇章、人物、世界觀與地點資料，以及如何設定多重章節解鎖。網站使用 `素材/web.json` 作為首頁小說清單；各小說再由自己的 `架構/web.json` 指向篇章和資料索引。網站不會直接讀取 Word 原稿，正文使用 Markdown，圖鑑和索引使用 JSON。

## 新增小說世界

在 `素材/web.json` 的 `novels` 物件內新增一筆：

```json
{
  "new-story": {
    "title": "新小說名稱",
    "description": "首頁顯示的小說簡介。",
    "cover": "素材/小說/新小說/圖片/封面.png",
    "Background": "素材/小說/新小說/圖片/背景.png",
    "configPath": "素材/小說/新小說/架構/web.json"
  }
}
```

`cover` 和 `Background` 可留空；首頁會使用全域預設圖片。圖片、索引及正文都應放在網站素材資料夾內，並依上例使用相對於網站根目錄的路徑。

小說架構檔的基本格式：

```json
{
  "version": 1,
  "id": "new-story",
  "title": "新小說名稱",
  "description": "小說世界介紹。",
  "story": {
    "description": "小說篇章列表上方的說明。",
    "arcs": [
      {
        "id": "main",
        "title": "主篇",
        "description": "進入篇章後顯示的副標題。",
        "index": "../劇情/主篇/index.json"
      }
    ]
  },
  "libraries": {
    "characters": { "title": "人物設定", "index": "../人物/index.json" },
    "world": { "title": "世界觀設定", "index": "../世界觀/index.json" },
    "maps": { "title": "地點設定", "index": "../地圖/index.json" }
  }
}
```

`id` 請保持唯一且穩定，避免更名後使舊有閱讀進度失去對應。各路徑以這份架構 `web.json` 的位置為基準。
小說首頁（小說世界總覽）的簡介欄位設在 `素材/web.json`；進入小說後顯示的世界介紹則讀取該小說架構檔根層的 `description`，兩者用途不同。

## 新增篇章與章節

每個篇章使用一個資料夾、一份 `index.json` 和多份 Markdown 正文：

```text
劇情/
└─ 主篇/
   ├─ index.json
   ├─ 001.md
   └─ 002.md
```

篇章索引範例：

```json
{
  "version": 1,
  "id": "main",
  "title": "主篇",
  "description": "篇章索引的說明。",
  "chapters": [
    {
      "id": "main-001",
      "number": "001",
      "title": "第一章",
      "file": "001.md",
      "summary": "在章節卡片顯示的簡短介紹。"
    }
  ]
}
```

章節 `id` 應在同一小說內唯一，並且不要在已有閱讀紀錄後任意更改。正文可以使用一般段落、`##` 至 `######` 小標題、粗體與斜體。第一行若使用 `# 標題`，閱讀器會把它視為主標題而不重複顯示。

篇章卡片優先顯示 `summary`，沒有時使用 `description`。將滑鼠移到卡片上可查看完整描述。

## 新增人物、世界觀與地點

每個圖鑑索引使用 `items` 陣列；人物、世界觀及地點項目可使用以下欄位：

```json
{
  "id": "magic",
  "name": "魔法",
  "tags": ["力量體系", "術式"],
  "summary": "簡短摘要，會先行公開。",
  "content": "解鎖後顯示的完整說明。",
  "initialStatus": "locked",
  "unlockAfter": ["main-003"],
  "unlockHint": "完成第三章後解鎖。"
}
```

- `id`：項目唯一識別字。
- `name`：圖鑑卡片及內容標題。
- `tags`：可搜尋的分類關鍵字。
- `summary`：顯示在列表選項上的簡介；打開詳細頁後不會再次顯示。若完整內容開頭與摘要相同，詳細正文會略過重複的摘要文字。
- `content`：完整資料；省略 `initialStatus` 時預設公開。
- `initialStatus`：`open` 或 `unlocked` 表示公開；`locked` 表示需符合解鎖條件。若標記為 `locked` 卻沒有任何解鎖章節，該內容會一直保持鎖定。
- `unlockHint`：鎖定時顯示的補充提示。
- `portrait`：人物頭像圖片路徑；圖片顯示在人物名稱與摘要旁。
- `image`：地點或地圖圖片路徑。
- `links`：可連到同一小說其他圖鑑項目的按鈕。

`portrait` 與 `image` 路徑以小說架構 `web.json` 為基準，例如 `../人物/圖片/角色.png`。

## 多個解鎖條件

`unlockAfter` 可以列出一個或多個章節 ID。多個條件的規則是**完成其中任一章即可解鎖**，不是必須全部完成：

```json
{
  "initialStatus": "locked",
  "unlockAfter": ["main-003", "side-002"],
  "unlockHint": "完成主篇第三章或外傳第二章後解鎖。"
}
```

每個條件都會顯示篇章、章節和閱讀完成狀態；點選條件可直接跳到該章。

## 將長篇設定拆成 `sections`

當同一人物或主題有不同劇透解鎖時，可用 `sections` 把詳細資料分段。每段各自設定標題、內容與解鎖條件：

```json
{
  "id": "hero",
  "name": "主角",
  "summary": "主角的基本介紹，不含劇透。",
  "sections": [
    {
      "id": "hero-basic",
      "title": "基本資料",
      "content": "基本人物資料。",
      "unlockAfter": ["main-001"]
    },
    {
      "id": "hero-secret",
      "title": "身世秘密",
      "content": "較後期才揭露的內容。",
      "unlockAfter": [
        { "arcId": "main", "chapterId": "main-008" },
        { "arcId": "side", "chapterId": "side-004" }
      ],
      "unlockHint": "完成主篇第八章或外傳第四章後解鎖。"
    }
  ]
}
```

- 未解鎖的分段會顯示鎖定提示，不顯示該段 `content`；其他已解鎖分段照常顯示。
- 每段 `unlockAfter` 同樣採「完成任一章即可解鎖」。
- 分段條件可使用全小說唯一的章節 ID 字串，也可用 `{ "arcId": "篇章 ID", "chapterId": "章節 ID" }` 指定篇章。
- 未設定某段的 `unlockAfter` 時，會沿用項目本身的 `unlockAfter`；未設定分段條件時，該段依分段的 `initialStatus`、再依項目的 `initialStatus` 判斷，兩者皆未設定時預設公開。
- 有設定 `unlockAfter` 的分段預設鎖定，直到完成條件中的任一章；此分段條件優先於項目的 `initialStatus`。可用分段自己的 `initialStatus` 明確指定 `open` 或 `locked`。
- 在使用 `sections` 的項目上，若另有頂層 `content`，該內容視為整筆資料的附加內容，並依項目層級的解鎖條件保護。通常建議把詳細文字全部放在 `sections`，避免解鎖層級混淆。
- `sections` 內的 `id` 請在該項目內保持唯一。

## 備份與安全提醒

目前介面、閱讀進度與書籤會儲存在使用者瀏覽器的 `localStorage`。網站的解鎖只是避免閱讀介面提前顯示內容，**不是保密機制**：靜態 JSON 中的文字仍可被直接讀取。修改或新增 JSON 後，請確認括號、逗號格式正確，並檢查每個索引路徑和章節 ID 都存在。
